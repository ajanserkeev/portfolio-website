# AGENTS.md — правила для AI-инструментов и разработчиков

Этот файл читают Claude Code, Cursor, Copilot, Codex и люди. Подробности — в `docs/`.

## С чего начать

1. `docs/01-brief.md` — что строим и зачем (концепция «Башня»).
2. `docs/02-implementation-plan.md` — архитектура, **контракты между подсистемами** (раздел 3), порядок работ.
3. Текущий план из `docs/plan/` — выполнять задачи строго по порядку и отмечать `- [x]`.

## Как работаем

- TDD: тест → убедиться, что падает → минимальный код → проходит → коммит.
- Одна задача плана = один коммит. Формат Conventional Commits, на английском (`feat:`, `fix:`, `test:`, `chore:`, `docs:`).
- Перед коммитом: `pnpm verify`, для изменений в `art/` — ещё `pnpm art:test`. Форматирование и порядок импортов чинит `pnpm biome check --write`.
- Если план расходится с реальностью (API другой версии, команда не работает) — исправить план в том же коммите и коротко написать причину.
- Не добавлять зависимости, которых нет в плане. Если без новой не обойтись — обновить план и обосновать.

## Нельзя

- React Three Fiber, GSAP и Lenis в 3D-пути, WebGPU-рендерер, блокирующий прелоадер.
- Слова внутри 3D. Все тексты — в `src/i18n/ru.ts` и `src/i18n/en.ts` с одинаковыми ключами.
- Править руками `src/assets/levels/*`, `src/assets/textures/*`, `art/screens/manifest.json`, `art/faces/manifest.json`. Они генерируются только командами `pnpm art:*`.
- Использовать `.`, `:`, `/`, `[`, `]` и пробелы в именах узлов GLB (разделитель — `__`, контракт 3.2).
- Хранить секреты в репозитории. Делать реальные вызовы LLM, Telegram и CRM в тестах — только фейки.
- Обращаться к `localStorage`/`sessionStorage` без `try/catch`.
- Использовать Blender, кроме 4.5 LTS.

## Код

- TypeScript: `strict`, `noUncheckedIndexedAccess`, `erasableSyntaxOnly` (без enum, namespace и parameter properties).
- Чистая логика — отдельные модули с тестами рядом (`*.test.ts`). Склейка с DOM и three.js — тонкие модули, их проверяет e2e.
- Файл больше ~250 строк — повод разделить по ответственности.
- Код, комментарии и коммиты — на английском. Интерфейс — RU по умолчанию и EN.
- Python (`art/`): `from __future__ import annotations`. В `towerlib/core` нет `bpy` — тестируется pytest; остальное тестируется внутри Blender.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm dev` | сайт локально |
| `pnpm verify` | lint, типы, юнит-тесты, сборка, бюджеты, e2e |
| `pnpm preview:lan` | сайт в локальной сети для телефонов (`?debug=1` — HUD с FPS) |
| `pnpm art:doctor` | проверить Blender и экспортёр glTF |
| `pnpm art:test` | pytest и тесты внутри Blender |
| `pnpm art:build <этаж> [--draft] [--no-bake]` | собрать этаж в `src/assets/levels/` |
| `pnpm art:preview <этаж>` | превью этажа из Blender |
| `pnpm art:compare <этаж>` | сверка Blender ↔ сайт (нужен запущенный `pnpm preview`) |
| `pnpm art:screens`, `pnpm art:faces`, `pnpm art:matcap` | атласы экранов и лиц, matcap |

## URL-параметры для отладки

- `?tier=high|lite|static` — принудительный уровень качества.
- `?debug=1` — `window.__tower` (состояние движка) и HUD.
- `?shot=<этаж>` — кадр одного этажа без интерфейса (постеры, сверка).

## Окружение команды

Windows + PowerShell. Все скрипты — на Node (`tsx`) и кроссплатформенные. Пути с пробелами — норма: процессы запускаются без shell, аргументы передаются массивом.
